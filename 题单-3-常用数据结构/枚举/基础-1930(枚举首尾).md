# 1930. 长度为 3 的不同回文子序列（枚举首尾字母）

题目来源：LeetCode 1930（第 249 场周赛 Q2）

## 题意

给定一个字符串 `s`，统计其中**长度为 3 且互不相同**的回文子序列的个数。

- **回文**：长度为 3 的回文必然是 `X_Y_X` 形式——首尾字符相同，中间字符任意（可与首尾相同，如 `"aaa"`）。
- **子序列**：不要求连续，按原顺序挑出 3 个字符即可。例如 `"aba"` 是 `"aabca"` 的子序列（取第 1、2、5 个字符）。
- **去重**：同一个回文字符串只计一次，不同的构造方式不重复计数。
- **数据范围**：`3 <= s.length <= 10^5`，仅含小写英文字母。

## 核心思路：枚举首尾字母，统计中间

对 26 个小写字母中的每一个 `alpha`：

1. 找到 `alpha` 在 `s` 中**第一次出现**的位置 `first` 和**最后一次出现**的位置 `last`；
2. 若 `last - first >= 2`，统计开区间 `(first, last)` 内**不同字符的种类数**，累加到答案；
3. 若 `alpha` 未出现，或区间内没有字符，则贡献为 0。

### 为什么只看最左、最右出现位置就够了？

- **充分性**：只要中间字母 `d` 出现在 `first` 与 `last` 之间，就能取「第一个 `alpha` + 该 `d` + 最后一个 `alpha`」构造出回文 `alpha d alpha`；
- **必要性**：任何 `alpha d alpha` 子序列的两个 `alpha` 下标必然落在 `first..last` 之内，中间的 `d` 也必然落在该开区间内。

所以「区间内不同字母数」恰好等于以 `alpha` 为首尾字母的合法回文种类数。

### 为什么不会重复计数？

每个长度为 3 的回文由 **(首尾字母, 中间字母) 二元组唯一确定**，且只在首尾字母对应的那一轮被统计一次，因此天然去重，满足题意「相同的子序列只计数一次」。

### 最终答案

对 26 个字母各自的计数**求和**，即为答案。

### 复杂度

- 时间：O(26n)，最坏约 2.6×10⁶ 次操作——「只有 26 个小写字母」这一常数把看似 O(n²) 的问题压到了线性，这是本题的核心观察；
- 空间：O(1)（只用常数个辅助数组）。

## 参考代码（C++）

```cpp
class Solution {
public:
    int countPalindromicSubsequence(string s) {
        int ans = 0;
        for (char alpha = 'a'; alpha <= 'z'; alpha++) { // 枚举首尾字母 alpha
            int i = s.find(alpha);    // 最左边的 alpha 的下标
            if (i == string::npos) {  // s 中没有 alpha
                continue;
            }
            int j = s.rfind(alpha);   // 最右边的 alpha 的下标

            bool has[26]{};
            for (int k = i + 1; k < j; k++) { // 统计中间不同字母数
                if (!has[s[k] - 'a']) {
                    has[s[k] - 'a'] = true;
                    ans++;
                }
            }
        }
        return ans;
    }
};
```

## 关键细节：中间不同字母的统计（has 去重）—— 计数核心

```cpp
bool has[26]{};
for (int j = l + 1; j < r; j++) {
    if (!has[s[j] - 'a']) {
        has[s[j] - 'a'] = true;
        ans++;
    }
}
```

**这段代码的作用**：统计开区间 `(l, r)` 内出现了多少种**不同的**字符，并累加到 `ans`。它是把「核心思路」变成「最终答案」的那一步——**整个算法的计数核心**。

**逐行解读**：

- `bool has[26]{}`：26 个标记位全部初始化为 `false`，`has[c]` 表示字符 `c` 是否已在本区间出现过；
- `for (int j = l + 1; j < r; j++)`：恰好遍历两个首尾 `alpha` 之间的每一个可能充当中间字符的位置；
- `s[j] - 'a'`：把字母映射成 0~25 的下标；
- `if (!has[...])`：只有**首次出现**的字母才被标记并 `ans++`，重复出现的字母直接跳过。

**为什么这段代码不能省略 / 去重不能去掉**（复现代码时最容易踩的两个坑）：

1. **漏掉整个统计循环** → `ans` 永远保持 0，任何用例都输出 0，全部失败；
2. **漏掉 `has` 去重（对每个位置都 `ans++`）** → 同一个中间字母出现多次会被重复计数，答案偏大。例如 `"bbcbaba"` 中 `b` 的区间 `(0, 5)` 内是 `b, c, b, a` 四个位置，按位置数会得 4，但不同字母只有 `{a, b, c}` 三种，正确答案是 3；
3. **去重正是题意「相同的子序列只计数一次」的代码落点**：中间字母相同 → 回文相同（如 `"aba"` 无论用区间里哪个 `b` 构造都只算一次）。

**小提示**：这段统计也可以用 26 位整数掩码等价实现：`int mask = 0; for (int j = l + 1; j < r; j++) mask |= 1 << (s[j] - 'a');` 最后把 `__builtin_popcount(mask)` 累加到 `ans`，效果完全相同。

## 补充：string::npos

- `string::npos` 是 `std::string` 的静态常量，表示「**没找到**」（值为 `size_t` 能表示的最大值，即 `-1` 转成无符号数）。
- `s.find(alpha)` 找不到时返回 `npos`，所以必须用 `i == string::npos` 判断。**不能用 `if (!i)`**（`!i` 只在 `i == 0` 时为真，而找到在下标 0 是合法的）；也不应依赖 `== -1`（规范写法就是和 `npos` 比）。
- 本段代码中 `find` 已判过 `npos`，因此 `rfind` 必然能找到，无需重复判断。

## 示例验证

- `"aabca"`：`a` 的区间 `(0, 4)` 内有 `{a, b, c}` → 3 个（`"aaa"`、`"aba"`、`"aca"`），答案 3 ✅
- `"adc"`：所有字母都满足 `last - first < 2` → 0 ✅
- `"bbcbaba"`：`b` 的区间 `(0, 5)` 内有 `{a, b, c}` → 3 个（`"bbb"`、`"bcb"`、`"bab"`）；`a` 的区间 `(4, 6)` 内有 `{b}` → 1 个（`"aba"`），共 4 ✅
