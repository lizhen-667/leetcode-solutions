## 📌 这个仓库是什么

这不是一份「题解合集」，而是一本**思考过程档案**。

大多数题解仓库只留下最后的 AC 代码，而真正让人进步的部分——**为什么想到这个解法、卡在哪里、怎么绕出来的**——往往被丢掉了。所以我的每一篇笔记都尽量保留三样东西：

| 记录内容 | 解决的问题 |
| --- | --- |
| **题意 → 数学式子的翻译过程** | 摆脱「读完题就猜算法模板」的撞大运式解题 |
| **公式变形与本质提取** | 理解解法的必然性，而不是记住解法的样子 |
| **易错点与反例** | 让「交一次过」变成常态，而不是靠补丁修 bug |

此外还有一个专门的[**失误档案**](#-失误档案关于一些代码语句的纠正和理解)目录，存放那些我自己踩过的坑（整数溢出、条件判断顺序、`upper_bound` 参数……）——犯过的错误写下来，就不会再犯第二次。

## 🧠 我的解题方法论：四步降维法

仓库的总纲是[《算法题-方法论》](算法题-方法论.md)——一套「先证后写，杜绝边写边猜」的解题流程：

| 步骤 | 动作 | 产出物 |
| --- | --- | --- |
| **① 纯数学建模** | 不动键盘，把题目文字翻译成最简数学公式 | 一个明确的数学式子 |
| **② 公式变形与特征提取** | 代数变形，挖掘几何/代数意义，寻找「元变量」 | 一个被简化的新表达式 |
| **③ 构造逻辑证明** | 证明充分性与必要性，主动寻找反例 | 一个「解法成立」的信念 |
| **④ 伪代码与边界锚定** | 先写伪代码，锚定空集、极值初始化、整数溢出三大边界 | 一次通过的代码 |

> **核心心得**：当你觉得一道题的解法很「巧妙」时，往往是你在**第二步（抽象变形）**看穿了本质，而不是代码技巧有多高超。**先练数学眼力，再练码力。**

一个典型例子是 [1749. 任意子数组和的绝对值的最大值](题单-3-常用数据结构/前缀和/基础-1749（前缀和%2B子数组和的绝对值的最大值）.md)：`max |Σ nums[l..r]|` 经过「前缀和相减 → 绝对值 → 数轴上两点距离」的层层降维后，答案直接就是 `max(prefix) - min(prefix)`，顺序无关，一次遍历解决。

## ✍️ 一篇笔记长什么样

笔记格式并不固定：早期是随手记的解题草稿，后期逐渐收敛成一套结构化模板（参见 [1749](题单-3-常用数据结构/前缀和/基础-1749（前缀和%2B子数组和的绝对值的最大值）.md) 与 [1310](题单-3-常用数据结构/前缀和/基础-1310（异或%2Bvector-reserve函数）.md)）：

```text
> 核心思想：一句话点明本质与复杂度

1. 题意概括        —— 用数学语言重述题目
2. 核心思路        —— 公式变形与特征提取的完整推导
3. 代码展示        —— 带注释的实现
4. 易错点分析      —— 表格化罗列踩坑点与正确做法
5. 复杂度分析      —— 时间 / 空间
6. 示例            —— 手动跑一遍验证推导
---
笔记心得            —— 这道题真正让我学到了什么
```

**为什么坚持写「易错点」和「笔记心得」？** 因为 AC 只证明这次对了，而写下易错点，才说明你真的知道自己差点在哪错。
